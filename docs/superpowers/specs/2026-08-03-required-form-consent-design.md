# Required Personal Data Consent Design

## Goal

Require explicit personal-data-processing consent before any LS Detailing lead form can submit.

## Scope

- Cover all 27 lead forms: the home-page consultation form, the contacts form, and all 25 service-page forms.
- Do not add the control to pages that do not collect personal data.

## Approved interaction

- Add one unchecked checkbox immediately before each submit button.
- Use the text: `Я даю согласие на обработку персональных данных и принимаю условия Политики конфиденциальности.`
- Make `Политики конфиденциальности` a link to the depth-correct `privacy.html` page.
- The submit button remains enabled.
- A submit attempt without consent must stop before any network request or WhatsApp fallback, mark the checkbox invalid, focus it, and show `Подтвердите согласие на обработку персональных данных.`
- A successful form reset returns the checkbox to its unchecked state.

## Shared implementation

- Service-page consent markup is generated by `build-services.py`.
- The root home and contacts forms receive equivalent markup.
- The shared JavaScript validator treats required checkboxes by their checked state rather than their serialized string value.
- Existing required name/phone behavior, honeypot behavior, service tracking, endpoint requests, and WhatsApp fallback remain unchanged.

## Accessibility and presentation

- Associate checkbox and text through a wrapping label.
- Keep the policy link keyboard accessible.
- Provide a visible focus indicator and an invalid state with sufficient contrast.
- Keep the checkbox and text readable without horizontal overflow on mobile.

## Cache and verification

- Increment CSS and JavaScript cache versions wherever the shared assets are referenced.
- Structural tests verify exactly one required consent checkbox in every lead form and a depth-correct policy link.
- JavaScript tests or browser checks verify unchecked submission is blocked and checked submission reaches the existing delivery path.
- Browser checks cover home, contacts, and a service page on desktop and mobile.
