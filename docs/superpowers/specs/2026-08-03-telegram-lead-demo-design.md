# Временный Telegram-бот заявок LS Detailing

## Цель

Продемонстрировать пункт ТЗ о передаче новых заявок сайта менеджеру в Telegram. Бот работает как односторонний канал уведомлений и не ведёт переписку с клиентами.

## Согласованный объём

- Бот: `@ls_detailing_leads_bot`, отображаемое имя «ls_detailing».
- Получатель: закрытая группа «LS Detailing — заявки».
- Режим работы: временный локальный запуск на компьютере владельца сайта.
- Бот отправляет одно структурированное сообщение на каждую принятую заявку.
- Меню, команды для менеджеров, статусы обработки, ответы клиентам и постоянный хостинг не входят в эту демонстрацию.

## Архитектура

```text
локальная копия формы сайта
  → локальный Node.js API POST /api/leads
  → резервное сохранение в leads.ndjson
  → Telegram Bot API sendMessage
  → закрытая группа менеджеров
```

Статический публичный сайт во время демонстрации не переключается на временный локальный адрес. Форма и API запускаются на одном компьютере, а доступ к Telegram выполняется серверной частью.

## Состав уведомления

В сообщении указываются:

- тип обращения;
- имя клиента;
- нормализованный номер телефона;
- выбранная услуга;
- комментарий, если он заполнен;
- URL страницы;
- UTM-источник, если он присутствует;
- внутренний ID сохранённой заявки.

Телефон остаётся обычным текстом, чтобы Telegram распознавал его и позволял менеджеру быстро скопировать номер или позвонить.

## Конфигурация и безопасность

- `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` задаются только в локальном файле окружения.
- Локальный файл окружения исключается из Git и не публикуется вместе с сайтом.
- Токен не передаётся браузеру и не записывается в HTML или JavaScript сайта.
- В документации и тестах используются только фиктивные значения.
- После демонстрации текущий токен следует отозвать и выпустить заново, поскольку он был передан в переписке.

## Обработка ошибок

Сначала API валидирует и сохраняет заявку, затем пытается отправить уведомление в Telegram. Вызов Telegram ограничен тайм-аутом. Если Telegram временно недоступен, API не удаляет сохранённую заявку и не раскрывает клиенту внутреннюю ошибку или реквизиты бота.

## Проверки

- Telegram `getMe` подтверждает правильного бота.
- Тестовое `sendMessage` доставляется в согласованную группу.
- Автоматический тест проверяет адрес Bot API, ID чата и основные поля уведомления с фиктивным токеном.
- Тестовая заявка из локальной формы сохраняется в резервный файл и появляется в Telegram-группе.
- Невалидная заявка не отправляется в Telegram.
- Ошибка Telegram не приводит к потере уже сохранённой заявки.

## Критерий готовности

Владелец заполняет локальную форму сайта, после чего в закрытой группе появляется корректное уведомление с данными заявки, а копия заявки остаётся в локальном резервном файле.
